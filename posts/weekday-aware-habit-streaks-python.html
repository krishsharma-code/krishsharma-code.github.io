Your Habit Streak Is Lying to You Every Tuesday

26 November 2026 · Krish Sharma

Open almost any habit tracker and create a habit that runs Monday, Wednesday and Friday. Tick off Monday. Tick off Wednesday. Then let Thursday and the weekend pass without a single check-in — because nothing was due — and watch what the app does on the following Monday.

It says 1.

You did exactly what you promised. The app counted the days you were never asked to show up, called them misses, and threw the run away. That is not a habit problem. It is an arithmetic problem, and it is the one I set out to fix in streak-board, the newest module in my daily-dev-workspace repository.

The problem: streaks are counted in calendar days, habits are not

Most streak implementations store check-ins and then walk backwards one day at a time, asking "did anything happen on this date?". It works beautifully for a daily habit and breaks for every other kind.

Two bugs follow from that single shortcut.

The off-day bug. A habit scheduled three days a week is measured against seven days a week. Tuesday is not a failure, it is a rest day, but the counter does not know the difference. Anyone training on a schedule rather than daily is punished by the UI for following the plan the UI was given.

The today bug. The other half is subtler. If a habit is due today and you have not ticked it yet, most implementations count that as a miss and reset the streak at 9 a.m. The day is not over. Counting it as a failure at breakfast is like marking an exam before the student sits it.

Underneath both sits a quieter bug: timestamps. A check-in at 23:59 and one at 00:01 are different days, and a system that stores instants instead of days will eventually disagree with itself.

How it works: three rules, one pure function

The whole engine lives in fullstack-mix/streak-board/server/streak.py and it is pure functions over datetime.date objects — no database, no clock, no sockets. That matters: "what counts as an unbroken run" is the interesting part, and it is easier to trust when it can be tested without a server.

A habit stores its due days as ISO weekday numbers, Monday 0 through Sunday 6. From that, three rules cover every case:

  1. A due day with a check-in extends the run.
  2. A due day in the past with no check-in ends it — that is the entire point of a streak.
  3. Today, if due and not ticked yet, is skipped rather than counted as a miss. The day is still in progress, and checking in later today extends the run instead of restarting it at 1.

Rule three is the reason the current streak needs a reference day while the longest streak does not. Here is the actual function, unchanged from the repo:

def current_streak(
    days: Iterable[object], today: object, weekdays: object = None
) -> int:
    """How many scheduled days in a row are done, counting back from today.

    * A checked-in scheduled day extends the streak.
    * Today, if scheduled and not yet done, is skipped rather than counted as a
      miss -- the day is still in progress.
    * Any earlier scheduled day without a check-in ends the run.
    """
    today = parse_day(today)
    done = {day for day in _as_day_set(days) if day <= today}
    days_of_week = normalise_weekdays(weekdays)

    if today.weekday() in days_of_week and today in done:
        cursor: Optional[date] = today
    else:
        cursor = previous_scheduled_day(today, days_of_week)

    streak = 0
    while cursor is not None and cursor in done:
        streak += 1
        cursor = previous_scheduled_day(cursor, days_of_week)
    return streak

Read the middle block again: that is where both bugs die. If today is due and already ticked, the walk starts at today. Otherwise it starts at previous_scheduled_day — the latest due day strictly before today, which skips both the unfinished today and every rest day in one step. The loop then hops backwards between due days only, so a Monday-to-Monday run across a quiet weekend counts as two, not as a reset.

parse_day is deliberately strict: 2026-1-5, 2026-01-05T10:00 and 05-01-2026 are rejected rather than guessed at, because a log that records the wrong day is worse than one that asks again.

What's new in this release

The commit that landed this week (efaeb4a, feat(fullstack-mix): add streak-board for weekday-aware habit streaks) adds a complete, self-contained project rather than a snippet:

  • A stdlib server. server/app.py is a http.server router that also serves the front end from the same origin, so there is no build step, no framework and no third-party package anywhere in the tree.
  • SQLite storage. server/store.py keeps habits and check-ins in sqlite3, defaulting to :memory: and persisting with STREAK_BOARD_DB=habits.db. Habit ids are slugs of the name, so "Read 20 pages" becomes read-20-pages. Check-ins are idempotent — repeating one is a no-op, not an error — and deleting a habit cascades to its history.
  • A tolerant weekday parser. weekdays accepts "daily", "mon,wed,fri", ["Mon", "Wed"], [0, 2, 4], or nothing at all for every day, and normalises all of it into one sorted, de-duplicated tuple.
  • A 30-day completion window measured against due days. A Saturday-only habit is scored against Saturdays, not against 30 calendar days, so a perfect month is genuinely 100%. The payload also lists the exact days that were missed.
  • Backfill yes, future no. A check-in may be dated in the past, but never in the future — a streak that can be pre-filled says nothing about whether anything was done.
  • Reproducible tests. Every route accepts ?today=YYYY-MM-DD to pin the reference day, so the suite never touches the clock. The full run is 111 passing tests across the engine, the store and the HTTP routes, including end-to-end tests that boot a real server on an ephemeral port.

You can try the engine without a socket: python server/example.py creates habits, checks in and prints the resulting streaks.

Roadmap

These are directions I would like to take it next; none are in the repo yet:

  • A configurable day boundary, for late-shift check-ins past midnight.
  • An optional "flex day" allowance for habits that tolerate one slip without losing the run.
  • Export and import of check-in history as plain JSON.
  • A calendar heatmap showing due, done and rest days as three distinct states.

Conclusion

A streak is a promise you made to yourself, and software that resets it for reasons you never agreed to is teaching you to distrust your own record. The fix is not a bigger feature list — it is deciding, once, what "due" means and then counting nothing else.

Three rules, one pure function, and a habit tracker that finally understands that Tuesday was never the point.

The code is open: daily-dev-workspace/fullstack-mix/streak-board. Clone it, run python server/app.py, and tell me which rule your favourite tracker gets wrong — or open an issue if you spot a case the engine still misses.
